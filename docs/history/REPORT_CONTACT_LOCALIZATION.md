# 有孔模型接触部件定位

日期：2026-09-22。结论：已确认原始孔碰撞分块上表面存在大面积重叠，并且重复参与接触会显著改变固定状态下的轴向力。本轮只定位问题，尚未修改碰撞资产或控制器。

## 1. 方法

回放上轮保存的15个时间点×3种工况，共45个状态。导出geom ID、body、mesh、CPU/GPU接触位置（孔坐标系）、法向、穿透量及CPU接触力。上一轮几何名称为空的问题用ID及mesh/body映射解决，原先接触数统计仍成立。

进一步读取原始OBJ的顶面三角形，逐点检查接触位置被哪些网格覆盖。确认各Part子body的局部位姿均为零平移、单位旋转，使用原始OBJ坐标与孔局部坐标一致。

## 2. 具体部件

所有这些接触的轴侧均为`robot/peg_pa2`，碰撞geom ID为29。其视觉geom ID为28，contype/conaffinity均为0，没有重复参与碰撞。

|工况|CPU持续参与的主要孔部件|CPU接触数|GPU接触数|
|---|---|---:|---:|
|5 mm X+|Part1-47至Part1-61；个别状态还有62或Part2-5|15–17|2–4|
|5 mm Y−|Part1-65至Part1-70|6|1–3|
|20 mm X−|Part1-30至Part1-41|12|1–3|

完整名称前缀为`hole/Assem1 - `。多数接触法向接近孔坐标系的负Z方向，接触点位于上表面附近。不是孔内壁深处的卡滞。

相关定义位于`assets/hole/Hole35.xml`：Part1-32始于182行，Part1-48始于246行，Part1-54始于270行，Part1-65始于314行。

## 3. 已确认的几何问题

这些分块是围绕孔排列、相互大幅覆盖的实体，并非只在边界拼接的扇形块。重叠直接存在于原始OBJ顶面三角形中，不仅仅是对MuJoCo凸包行为的推测。

以第0号状态为例：

- **5 mm X+：**Part1-48至57在约`(-14.1277, -14.7980, -0.00824) mm`处形成10个间距小于1微米的CPU接触点，来自10个独立碰撞geom。
- **20 mm X−：**Part1-32至41在约`(12.7686, -15.8208, -0.00708) mm`处同样形成10个近乎重合的CPU接触点。
- **5 mm Y−：**接触点没有形成同样的10点聚类，但其接触区域仍被多块顶面覆盖；一个示例位置由Part1-65至70共6块顶面覆盖。
- 在另外两个工况的部分接触位置，原始顶面覆盖数量达到12块。

这些是同一物理支撑区域上的重复约束。接触数差异不是“CPU更精确地找到同一块网格上的多个分散支撑点”这么简单。

![重叠顶面与接触位置](../../evaluation/probe_contact_localization/top_overlap.png)

蓝色为实际参与CPU接触的原始OBJ顶面轮廓，橙色为CPU接触位置，黑色为GPU接触位置。相同位置的多点会在图上重合，不能从散点数量直接数出约束数量。虚线圆为名义35 mm孔径参考，不代表倒角顶端轮廓。

## 4. 固定状态因果对照

保持第0号状态的机器人位置、速度、执行器状态、控制指令、摩擦和求解参数不变。仅在内存中临时禁用指定重叠组的部分碰撞geom，其他几何仍参与，重新执行CPU forward。每次恢复同一输入状态。

|工况|重叠组保留数量|总接触数|轴端补偿Fz|
|---|---:|---:|---:|
|5 mm X+，Part1-48至57|1|6|32.58 N|
|同上|2|7|34.93 N|
|同上|5|10|39.99 N|
|同上|10|15|44.84 N|
|20 mm X−，Part1-32至41|1|3|21.27 N|
|同上|2|4|25.16 N|
|同上|5|7|32.39 N|
|同上|10|12|38.25 N|

这证实重复碰撞分块本身会改变轴向响应，不需要改变摩擦就能产生十多N的差异。数字是指定单个快照，不是上轮15个快照的均值。

该操作只用于定位原因，**不能直接作为修复方案**：这些分块还包含其他区域和孔壁，直接删除会破坏完整碰撞覆盖。也未证明GPU为什么遗漏某些几何对；后端差异的全部机制仍需复核。

## 5. 摩擦设置补充核实

上一轮只看机器人XML顶层默认值不够准确。编译后的轴碰撞geom实际为`condim=3`、`friction=[1.0,0.005,0.0001]`；孔的分块为`condim=4`、`friction=[0.9,0.2,0.2]`。

本次检查实际生成的接触：`dim=4`，五维摩擦数组为`[1.0,1.0,0.2,0.2,0.2]`。前两项是两个滑动方向，第三项为扭转；后两项在dim=4时不启用。因而实际滑动系数为1.0，不能直接用孔侧XML的0.9代表接触参数。

扭转摩擦仍值得后续校准，但它不是解释本次重复顶面约束所必需的条件。

## 6. 修复建议

优先修复孔的**碰撞表示**：将上表面、倒角和内壁重构为外表面连续、相邻块内部不重叠的凸分块；保留原视觉资产。必须保持孔径、轴孔间隙、倒角与深度，并检查接缝与分块精度。

避免两个捷径：直接删除本次出现的Part（其他位置会缺面）；把整个有孔环体做成一个普通凸碰撞网格（可能把孔填实）。

修复后先复用这45个状态复核外形覆盖、接触位置、轴向力和CPU/GPU趋势，再运行小幅摆动。当前证据足以优先处理重叠几何，但不能提前承诺消除所有动态超载或后端差异。

## 产物与复现

- `evaluation/probe_contact_localization/catalog.json`：全部geom的ID、body、mesh、碰撞属性映射。
- `contacts.json`：45个状态的定位数据。
- `summary.json`：每个几何对的参与次数。
- `top_overlap.json`：原始OBJ顶面对各接触位置的覆盖计数。
- `overlap_ablation.json`：固定状态重叠数量对照与实际摩擦参数。
- `scripts/localize_probe_contacts.py`：位置与部件回放。
- `scripts/analyze_contact_overlap.py`：顶面重叠验证与图。
- `scripts/ablate_overlap_contacts.py`：临时内存碰撞屏蔽对照。

```bash
bash scripts/run_local.sh python scripts/localize_probe_contacts.py evaluation/probe_cpu_gpu_hole --output evaluation/new_contact_localization
bash scripts/run_local.sh python scripts/analyze_contact_overlap.py
bash scripts/run_local.sh python scripts/ablate_overlap_contacts.py
```

后两个脚本读取/写入固定的`evaluation/probe_contact_localization`目录。它们不改变XML、OBJ或控制参数。
