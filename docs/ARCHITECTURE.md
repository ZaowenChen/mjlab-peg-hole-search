# 架构与兼容边界

`mjlab_contact_20n` 是当前唯一开发主线，包名继续使用 `mjlab_contact_prep`。本轮只整理职责，不改变控制常数、PPO 奖励、成功条件或故障优先级。

## 源码职责

| 目录 | 职责 |
|---|---|
| `simulation/` | 模型、资产、碰撞、后端、复位与随机采样 |
| `control/` | 接触状态机、执行动作、力矩处理和锥形参考 |
| `envs/` | actor/critic 观测、动作、奖励、终止与分布环境 |
| `data/` | 完整物理/控制/历史状态库及格式兼容 |
| `training/` | PPO 配置、队列、保存与恢复 |
| `evaluation/` | 独立评估、轨迹审计、统计与报告 |

正式实验冻结时使用的顶层模块和 `night_run/` 文件保持原字节不变。新职责子包是后续代码的稳定入口，并转发到冻结实现；因此历史导入和源码哈希核验同时有效。以后迁移实现时，应逐个模块增加固定案例对照，再把旧路径变为兼容转发层。

## 关键合同

- 控制器不读取未知孔位真值。孔位真值仅用于复位、训练奖励和离线评估的既有合同。
- 状态库保存 MuJoCo 物理字段、控制器、动作项、探测器及环境历史；不能只保存关节位置。
- 在线 `ready` 是动作许可，不等于离线持续稳定合格。
- 成功仍为连续 0.2 s 稳定浅入孔，不是完整插入。
- `evaluation/`（根目录）保存运行产物；`src/mjlab_contact_prep/evaluation/` 保存评估程序。
